# Epic 00 - prettier-header CLI 基础能力

## 1. 背景

`prettier-header` 是一个 CLI 工具，用来生成更美观、统一的标题注释，例如：

```txt
/*//////////////////////////////////////////////////////////////
                        EXTERNAL
//////////////////////////////////////////////////////////////*/
```

当前仓库仅有一句项目描述，尚未明确产品边界、用户场景、命令设计和验收标准。本 PRD 用于定义 Epic 00 的第一阶段目标。

## 2. Epic 目标

- 提供一个可用的 CLI，能快速生成好看的标题注释。
- 让开发者不需要手动数分隔符、对齐文本或重复复制模板。
- 为后续扩展语言风格、模板系统和文件写回能力打下基础。

## 3. 非目标

- 暂不覆盖完整代码格式化能力。
- 暂不替代 Prettier、ESLint 等现有格式化/静态检查工具。
- 暂不默认支持复杂模板编排，除非后续问答明确纳入 Epic 00。

## 4. 目标用户

主要面向希望快速生成代码分区标题注释的 CLI 用户。

当前优先场景：

- 需要经常插入 header 注释的开发者。
- 希望通过终端快速生成并直接粘贴到编辑器中的用户。
- 对注释风格有偏好，希望按 pattern 选择样式的用户。
- 偏好视觉化分区标题，尤其是双线框样式和单行强调样式的用户。

## 5. 核心问题

开发者在代码中书写分区标题时，通常会遇到这些问题：

- 标题注释需要手动对齐，耗时且容易不一致。
- 团队内不同人使用不同风格，代码可读性不统一。
- 想快速生成类似大标题样式时，缺少简单、直接的工具。

## 6. 用户故事

### 6.1 主用户故事

作为一名开发者，我希望输入一段标题文本后，CLI 能输出格式统一、视觉好看的标题注释，这样我可以直接复制或写入代码文件中。

### 6.2 待确认的扩展用户故事

- 作为一名开发者，我希望指定注释风格，以适配不同语言或团队规范。
- 作为一名开发者，我希望先查看所有可用样式，再选择其中一种生成标题注释。
- 作为一名开发者，我希望生成结果自动进入剪切板，这样我能直接粘贴到编辑器中。

## 7. 范围

### 7.1 In Scope

Epic 00 当前已确认纳入：

- 使用 `phmx` 作为 CLI 命令入口。
- 输入标题文本，生成单个标题注释块。
- 支持通过位置参数传入标题文本。
- 支持通过 `-p` / `--pattern` 选择注释样式。
- 支持通过 `-l` / `--list` 查看所有可用样式。
- 生成结果默认保存到系统剪切板。
- 首发内置 2 个 pattern。
- 提供默认样式，且支持后续扩展多个 pattern。

### 7.2 Out of Scope

当前默认排除：

- 扫描整个代码库并自动插入标题。
- IDE 插件能力。
- 复杂交互式 UI。
- 多段注释模板批量生成。
- 直接修改目标源码文件。

## 8. 命令行体验

当前已确认：

- 命令名称为 `phmx`。
- 不强制引入子命令，默认直接执行生成逻辑。
- 支持缩写参数 `-p`、`-l`。
- 标题文本作为位置参数输入。
- 默认行为是生成结果输出到终端，并同步写入系统剪切板，而不是写入文件。
- 首发内置 2 个 pattern，其中默认 pattern 为双线框样式。
- `--list` 以带序号的列表展示 pattern，并附带样例预览。
- pattern 标识符直接使用 `1` 和 `2`。
- 标题文本默认原样保留，不自动转换大小写。
- Epic 00 采用固定宽度，不提供宽度调节参数。
- 无论剪切板写入是否成功，生成结果都始终打印到终端。
- 首发仅支持 macOS 的系统剪切板能力。

候选示例：

```bash
phmx "Auction Participation"
phmx -p 2 "Auction Participation"
phmx --list
```

`--list` 候选展示形态：

```txt
1. 1
// ================================================================================================
// │                                    Auction Participation                                     │
// ================================================================================================

2. 2
<<<=========--Auction Participation --========>>>
```

默认 pattern 示例：

```txt
// ================================================================================================
// │                                    Auction Participation                                     │
// ================================================================================================
```

第二个首发 pattern 示例：

```txt
<<<=========--Auction Participation --========>>>
```

## 9. 功能需求

### 9.1 必须有

- 输入标题文本并生成结果。
- 支持 `-p` / `--pattern` 选择样式。
- 支持 `-l` / `--list` 查看可用样式。
- `--list` 输出需包含序号与样例预览。
- 将生成结果稳定写入系统剪切板。
- 无论剪切板写入是否成功，生成结果都输出到终端。
- 对输出进行稳定的宽度和对齐处理。
- 标题文本默认按原样输出。
- 错误输入时给出明确提示。

### 9.2 应该有

待确认：

- 在写入剪切板成功后输出简洁确认信息。

### 9.3 可以有

待确认：

- 读取配置文件。
- 交互式模式。

## 10. 非功能需求

- 输出结果应稳定、可预测。
- CLI 学习成本应尽量低。
- 错误信息应可读。
- 默认行为应尽量无副作用。
- 剪切板写入应兼容用户常见终端环境，失败时应明确报错。

## 11. 验收标准

当前候选标准：

- 用户能通过 `phmx "TITLE"` 一条命令生成标题注释，输出到终端，并写入剪切板。
- 用户能通过 `phmx --list` 查看全部 2 个首发样式，并看到序号与预览样例。
- 用户能通过 `phmx -p <pattern> "TITLE"` 使用指定样式生成结果。
- 相同输入在相同参数下总是得到相同输出。
- 固定宽度和文本对齐符合预期规则。
- 标题文本默认按输入原样保留。
- 无效参数、未知 pattern 时，CLI 返回非 0 退出码并输出错误信息。
- 剪切板写入失败时，CLI 仍将生成结果输出到终端，并明确提示剪切板写入失败。

## 12. 成功指标

待确认，候选指标：

- 新用户在 1 分钟内可生成第一个标题注释。
- 默认命令无需阅读复杂文档即可使用。
- 生成结果可直接粘贴到目标代码中。

## 13. 依赖与约束

待确认：

- 是否限定 Node.js 生态？
- 是否要求零依赖或尽量少依赖？
- 首发仅要求兼容 macOS 剪切板，不要求 Linux / Windows。

## 14. 未决问题

- 第一阶段要不要只服务某一类注释风格，例如代码注释 header，而不追求多语言语义适配？
- 终端输出是否只打印生成结果本体，还是附带一行简短状态提示？
